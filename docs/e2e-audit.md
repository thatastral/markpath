## Questions for the owner

1. **Hosted password reset.** `src/server/auth/reset.ts` sends email only when `RESEND_API_KEY` and `MARKPATH_MAIL_FROM` are set. Otherwise it logs the link in development and does nothing in production, but the UI still says "a reset link is on its way". Are both variables set on Vercel? If not, password reset is a dead end in production.
2. **Uploads on Vercel.** Guidelines and logos are written to `/tmp/markpath/uploads` on Vercel (`src/server/brand/service.ts:11`). That folder is per instance and is wiped between cold starts. Should the reference logo the Design agent compares against live in the database or in Blob instead?
3. **Website reading on Vercel.** Locally, reading stripe.com took 9.0 s and linear.app took 15.9 s. What is the function `maxDuration` for `/onboarding` on Vercel? Hobby plans default to 10 s, so linear.app may time out in production.
4. **Should "Skip setup for now" and "Finish later" mark onboarding as done?** Today, `/` keeps sending an un-onboarded workspace back to `/onboarding`, and the onboarding screen has no sign-out, workspace switcher or theme control.
5. **What should happen to issues after an approved fix is applied?** In the demo, the activity log says "Design Agent applied the approved change: applied, re-inspected in Figma" at 04:59. The six Figma issues (including `#164B9B`) are still open, and the dashboard shows "0 fixes verified". Is this stale demo data or a missing state transition? I could not tell which from the UI.
6. **Is the dashboard meant to be read-only for issues?** Issues have no actions at all: you can't request a fix, dismiss, mark as not an issue, or open the place in Figma. If chat is the only control surface by design, the page should say so where the actions would be.

### Console and network

- During this session's flows I saw no new console errors from the app.
- The console buffer held earlier errors from before my session: `Only plain objects … can be passed to Client Components … host={RegExp}` and a `GET /integrations 500` at log lines 2825 and 2842. `grep "host={"` finds nothing in `src/` now and `/integrations` returns 200, so this looks already fixed.
- A hydration-mismatch warning about `<details open="">` in the sidebar appeared after I toggled the workspace menu by script, so it is probably caused by my test, not the app. The menu does persist its open state across client navigation (F15).
- No failed network requests on any audited page. The device-flow poll `POST /api/integrations/github/poll` takes about 1 s per call.

## Local vs hosted differences to watch

- **Email.** Reset links are only printed to the dev log locally. In production they need Resend (Questions 1).
- **File storage.** Local `data/uploads` vs Vercel `/tmp/markpath/uploads`, which is ephemeral (Questions 2).
- **Long server actions.** Website reading took 9 to 16 s locally (Questions 3).
- **Database.** Local SQLite vs hosted Turso/libSQL. The lead noted named parameters failed remotely. Every action exercised here (sign-up, workspace create, brand save and approve, logo, integrations links, password reset, workspace switch) ran only against SQLite, so each needs a hosted smoke test.
- **Clipboard.** Copy buttons rely on `navigator.clipboard`, which needs a secure context and permission. Hosted HTTPS is fine, but F09 still applies when permission is denied.

## Observations

### What works well

- Validation copy on auth is short and specific ("Use at least 8 characters. This one has 5."). Errors clear as you fix them and focus moves to the first invalid field.
- Autofill attributes are correct (`email`, `current-password`, `new-password`, `name`). The password eye keeps focus in the field. A Caps Lock hint exists (`form-field.tsx`). Sign-up is case-insensitive for duplicate emails, and forgot-password avoids revealing which emails have accounts.
- The expired or used reset-link page is clear and offers "Send a new link".
- Markdown extraction is fast (9 ms) and accurate, with "Found in your source" chips to pick alternatives. A nice touch.
- Onboarding steps are deep-linkable (`?step=`), survive reload and browser Back, and the step list doubles as navigation.
- The Integrations page is honest: "A step turns green only after Markpath has used it". The Discord invite builder produces a correct OAuth URL with permissions.
- Theme and sidebar state persist through cookies with no flash. Collapsed icon links have titles. Muted text contrast is 5.3:1 in light and 6.6:1 in dark.
- At 375px no page scrolls horizontally. The mobile drawer moves focus in, closes on Escape and returns focus to the trigger.
- No unnamed interactive controls on any audited page. Exactly one `h1` per page.
- Empty states always offer a next step.

### Missing standard patterns (compared with Linear, Attio, Stripe and Vercel)

- **Command menu and shortcuts.** Linear and Vercel have Cmd+K and list shortcuts. Here only "[" (sidebar) is hinted.
- **Toasts for actions.** Stripe and Vercel confirm "Saved", "Approved" and "Password changed" with a toast. Markpath uses query-string banners or nothing.
- **Workspace settings.** No rename, delete, members or invite, and no account settings (change name, email or password while signed in). Attio and Linear expose these from the workspace menu.
- **OAuth redirect for GitHub.** Vercel and Linear connect GitHub with a redirect ("Install GitHub App"). The device-code flow is unusual for non-technical users.
- **Issue triage actions.** Linear-style rows normally carry status, assignee and a context menu (dismiss, snooze, open). Issues here are display-only.
- **Version history with diffs.** Stripe and Vercel show what changed between versions and allow rollback. Brand versions show neither.
- **Optimistic, inline progress for slow work.** Vercel shows build steps live. The 9 to 16 s website read shows only "Reading…".
- **Per-page document titles and favicon state.** Linear sets "Issues › Team"; Markpath uses one title for every app page.
